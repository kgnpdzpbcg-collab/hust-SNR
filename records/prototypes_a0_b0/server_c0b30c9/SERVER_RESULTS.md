- 源原文件：原服务器`hust/data/source/`，通过原架构实验的只读目录链接读取。
- 源缓存：复用原`gate0_v1`；没有重新划分、去重或切窗。
- 源训练：整记录逐相RMS校准高斯噪声，每轮按原随机流取10/15/20/25/30/35/40 dB；同时输入干净和含噪两个视图。
- 源验证：固定Clean及0/5/10/20/30 dB，0/5 dB复用原MAT，其余按原固定种子生成。三种子首轮训练噪声SHA与历史基线一致，五档验证逐数值与原随机流一致。
- 实测评估：原88个Dev文件、每档2474周期，六类周期数1106/307/297/298/237/229；共四档5/0/−5/−10 dB。没有使用目标标签训练或选权重。
- 5/0 dB来自`strong_snr_v1_20261012/generated/target`；−5/−10 dB分别复用`strong_snr_minus5_v1_20261014`、`strong_snr_minus10_v1_20261015`内已有波形，仅向新`extreme_dev`映射88个Dev编号，共176个符号链接。
- 两档负SNR均逐相、逐数值核对为本分支生成器的`Clean + (Author10 − Clean) × 10^((10−SNR)/20)`，时间、转速及原始行数保持。没有重复生成或增加独立噪声实现。四档为合成压力条件，不是四次独立采集。
- 仿真Source-Test及347个实测Final-Holdout没有参与训练、选模或评估。

## CUDA兼容性修正

原提交在真实GPU预检中因`median(dim=...).values`报错：当前PyTorch的该CUDA操作返回索引，不能在`torch.use_deterministic_algorithms(True)`下运行。正式训练当时尚未启动，原失败快照仍保留在服务器`prototypes_a0_b0/b0f97ce`目录。

本轮仅将噪声代理中的中位数换为稳定排序后取下中位数。固定20–80阶共61项，仍取第31项，没有改变数值定义、归一化、频带、网络结构、损失、随机数或训练配置。新增CPU/CUDA测试检查原中位数值及无并列值处的梯度一致；有并列值时中位数值相同，但选中元素的梯度分配可能不同。没有关闭确定性模式；服务器10项测试全部通过。
